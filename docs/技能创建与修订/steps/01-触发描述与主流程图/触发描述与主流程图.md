# 1 `create-skill` 的触发描述与流程

本步产出 `create-skill` 的触发描述和执行流程，请你审阅。流程页是唯一来源，文字版由它导出。建议先读文字版确认逻辑，再对照流程页修正，让图和文字一致。今后的做法是先画图，再在图的基础上整理出 skill 正文，所以图里的动作、条件和约束应当已经可以直接写进 skill。

## 1.1 触发描述

```yaml
name: create-skill
description: 当用户需要创建新的 skill，或调整已有 skill 的触发条件、执行流程或规则时使用。
```

例如，“把写发布说明的做法整理成 skill”应触发 `create-skill`。“根据这次变更写一份发布说明”应直接进入撰写发布说明的工作。

## 1.2 流程元素模型（待确认）

[流程元素模型](流程元素模型.md) 定义了 skill 流程的元素：步骤由按顺序执行的指令组成；指令分为执行、判断、提问三种；判断和提问产生分支，分支里可以放“进入步骤 N”“结束”这类流程指令；步骤只写出衔接用的关键输入输出；约束在执行出现偏差时才逐条补充。确认后，文字版导出、流程页展示和生图规则都以它为准。

## 1.3 流程页

流程页改为固定模板加流程数据：模板是 [assets/flow-template.html](../../../../skills/create-skill/assets/flow-template.html)，数据格式写在 [references/flowchart.md](../../../../skills/create-skill/references/flowchart.md) 第 5 节。create-skill 自己的流程页是 [flow.html](../../../../skills/create-skill/flow.html)，由模板生成并通过了校验；它导出的文字版就是现在的 SKILL.md。本目录下的各个候选版本已被模板取代。

文字版已经按流程元素模型改写，并作为第 02 步的产出，放在 [skills/create-skill/](../../../../skills/create-skill/SKILL.md) 下。流程页里的数据和展示还是改写之前的版本，需要按新的文字版和元素模型重新同步。
