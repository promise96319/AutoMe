# 需求是否适合做成 skill

## 1. 该不该做成 skill

同时满足以下三点时，适合做成 skill：

- 会多次重复去做。
- 输入、处理和输出可以沉淀成固定的流程。
- 直接用提示词容易出错或结果不稳定，需要用 skill 把流程和标准固定下来。

下面几种情况不适合做成 skill，按表中的做法推荐给用户：

| 情况 | 推荐的做法 |
| --- | --- |
| 只需要做一次 | 直接完成这次任务 |
| 模型本身已经能做得很好 | 直接完成，不写 skill |
| 只是某个项目的规则或约定，而不是一套流程 | 写进该项目的说明文件，例如 CLAUDE.md 或 AGENTS.md |
| 需要在某个事件发生时自动执行，例如“每次提交前”“每次改完文件后” | 配置 hook，由运行环境自动执行 |
| 输入、流程和输出都是确定的 | 写成脚本或工具 |

## 2. 用 skill 还是脚本

确定的事情交给脚本：输入是固定的参数、流程是确定的判断、结果也确定。脚本比 skill 更可靠，执行过程不占用上下文，每次结果一致。

不确定的事情交给 skill：输入是自然语言，流程需要模型判断，或者需要和用户对话澄清。skill 中确定性的环节，拆成 `scripts/` 下的脚本，由 skill 调用。
