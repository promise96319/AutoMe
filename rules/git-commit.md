# Git 提交规范

当前仓库有明确的提交约定时，优先遵循。其余按以下规则处理。

1. **提交范围。** 根据用户这次要求选择改动，核对暂存区的实际差异。同一文件混有其他任务的修改时，只纳入与本次任务相关的部分。
2. **提交说明。** 用一句话概括这次提交实际改变了什么。默认采用 `类型(范围): 摘要`，范围可以省略。例如 `fix(parser): 修复空配置导致的启动失败` 或 `docs: 补充本地安装示例`。当 Codex 参与完成本次改动时，在提交说明末尾空一行，追加 `Co-authored-by: Codex <noreply@openai.com>`。
3. **推送时机。** 用户要求提交时，创建本地 commit。用户同时要求推送时，核对远程仓库和目标分支，再执行推送。完成后说明提交号和实际推送结果。
